Generalidades

Objetivo

Brindar a los desarrolladores una guía para una fácil y rápida integración de los servicios
que ofrece Pagadito con las tecnologías con la que es compatible.

Público

Desarrolladores de Software, Encargados de Integraciones, Project Managers, Gerentes
de TI.

Resumen

Esta es una Guía de Integración para cada uno de los servicios que ofrece Pagadito a
los Desarrolladores y Comercios. Se ofrece una descripción para cada uno de los
servicios, los pasos de cómo funciona, un diagrama de la interacción entre tu sitio web
con Pagadito y códigos de ejemplo para cada tecnología con la que Pagadito es
compatible.
Con esta guía podrás comprender cómo funciona cada servicio y lograr una fácil y rápida
integración de tu sitio web con Pagadito, tanto con su plataforma de pruebas SandBox
como con su ambiente de producción.

SandBox

Pagadito cuenta con una plataforma de pruebas para que realices todas las pruebas que
necesites durante la integración de tu sitio web, aplicación o sistema con Pagadito.
Puedes ingresar haciendo click en https://sandbox.pagadito.com/.

Contacto

Para cualquier duda, por favor contáctanos a nuestro correo electrónico
developers@pagadito.com.

Pago con Tokenización

Descripción

Consiste en el procesamiento de pagos para un Comercio sin redirección, donde el
comercio le solicita al usuario los datos de su Tarjeta de crédito/débito y los envía a
Pagadito. Adicional al cargo a la tarjeta, Pagadito genera un token asociado a la tarjeta,
para poder hacer cargos futuros utilizando únicamente este token en lugar de todos los
datos de la tarjeta. Este servicio no requiere que el usuario sea redireccionado a una
pantalla de pago, por lo que tu sitio web o app es la encargada de todo el proceso de
pago. La comunicación con Pagadito es a través de una API REST.

Uso

Es una variante del procesamiento sin redirección, ideal para sitios web o aplicaciones
que reciben pagos con tarjeta de crédito/débito, donde ya se solicitan los datos de tarjeta
de crédito/débito del usuario, y que realiza cargos a la tarjeta sin requerir nuevamente
dichos datos.

Pasos

    1. El usuario llega a tu sitio web, elige los productos o servicios a pagar e ingresa los
         datos de su tarjeta de crédito/débito.

    2. Tu sitio web envía a Pagadito los datos del pago.
    3. Pagadito procesa el pago.
    4. Pagadito retorna la información del pago incluyendo el token de la tarjeta de

         crédito/débito.
    5. Tu sitio web muestra una pantalla de confirmación.

Código

Para conectarse a la API, su servidor debe admitir conexiones HTTPS:
    · HTTP/1.1
    · TLS 1.2

El encabezado de la solicitud:
    · "Content-Type" debe establecerse en "Application/json;charset=UTF-8"
    · "Content-Length" debe establecerse la longitud en bytes de los parámetros de
         solicitud.

Generar Device Fingerprint
Antes de enviar la petición de cobro, debes generar el Device Fingerprint del usuario.
Este dato se genera con base a sus datos de navegación; para ello debes incluir la
librería y agregar un input en el formulario de tu sitio web o aplicación con el dato
generado. Pagadito utiliza de forma segura este dato para analizar el nivel de riesgo de
la transacción.

Suscripción con Tokenización

Descripción

Consiste en el procesamiento de pagos y programación de cobros a futuros para un
Comercio sin redirección, el comercio le solicita al usuario los datos de su Tarjeta de
crédito/débito y los envía a Pagadito. Adicional al cargo a la tarjeta, Pagadito genera un
token asociado a la tarjeta, para poder hacer cargos futuros utilizando únicamente este
token en lugar de todos los datos de la tarjeta. Este servicio no requiere que el usuario
sea redireccionado a una pantalla de pago, por lo que tu sitio web o app es la encargada
de todo el proceso de pago. La comunicación con Pagadito es a través de una API
REST.

Uso

Ideal para sitios web o aplicaciones que ofrecen suscripciones con paquetes definidos,
es decir, que el usuario sabe el número de pagos que se le cargarán a su cuenta de
forma periódica. Con este servicio, tu sitio web o aplicación debe solicitar los datos de
tarjeta de crédito/débito del usuario una sola vez, y se realizaran los cargos a la tarjeta
en las fechas definidas.

Pasos

    1. El usuario llega a tu sitio web, elige los productos o servicios a pagar e ingresa los
         datos de su tarjeta de crédito/débito.

    2. Tu sitio web envía a Pagadito los datos del pago.
    3. Pagadito procesa el pago.
    4. Pagadito retorna la información del pago incluyendo el código de la suscripción y

         el token de la tarjeta de crédito/débito.
    5. Tu sitio web o aplicación, muestra una pantalla de confirmación.

Suscripción con Tarjeta Tokenizada

Descripción

Consiste en el procesamiento de pagos y programación de cobros a futuros para un
Comercio sin redirección, utilizando el token de una tarjeta de crédito/débito procesada y
tokenizada previamente. Este servicio no requiere que el usuario sea redireccionado a
una pantalla de pago, por lo que tu sitio web o app es la encargada de todo el proceso
de pago. La comunicación con Pagadito es a través de una API REST.

Uso

Ideal para sitios web o aplicaciones que ofrecen suscripciones escalables o la
renovación de una suscripción finalizada. Con este servicio, tu sitio web o aplicación
podrá enviar nuevos cargos sin necesidad que el usuario esté presente o que este
vuelva a ingresar los datos de su tarjeta de crédito/débito.

Pasos

    1. El usuario llega a tu sitio web, elige los productos o servicios a pagar e ingresa los
         datos de su tarjeta de crédito/débito.

    2. Tu sitio web envía a Pagadito los datos del pago.
    3. Pagadito procesa el pago.
    4. Pagadito retorna la información del pago incluyendo el código de la suscripción y

         el token de la tarjeta de crédito/débito.
    5. Tu sitio web o aplicación, muestra una pantalla de confirmación.

Webhooks

Descripción

Los Webhooks son callbacks HTTP que reciben notificaciones para los tipos de eventos
a los que están configurados. Son asíncronos, el orden no está garantizado y al ser
enviado más de una vez su resultado no cambia.

Uso

Ideal para sitios web o aplicaciones que necesitan una confirmación asíncrona del
cambio de estado de sus transacciones. Con este servicio, tu sitio web o aplicación no
quedará sin conocer el último estado de cada transacción.

Configuración

Desde la sección Configuración Técnica -> Webhooks, debes agregar la URL escucha y
guardar la configuración.

Eventos

Son notificaciones que se envían a la URL configurada, cuando disparador es activado,
como por ejemplo el cambio de estado de un pago. Cuando se produce un evento,
Pagadito notifica a través de una petición POST HTTP, la cual contiene los detalles del
evento y la información de la transacción.

Tipos
Los tipos de eventos son los diferentes disparadores que activan el envío de una
notificación. Los tipos de eventos soportados actualmente son los siguientes:
· TRANSACTION.STATUS.CHANGE: Este evento es disparado cuando un pago es

    registrado. También cuando cambia de estado a completado, en verificación,
    rechazado y expirado.

                                                                                                                             39
Información

formato JSON. Si la aplicación no está disponible o toma demasiado tiempo para

20 veces durante 3 días. El parámetro event_type indica el disparador del evento.

Firma
Cada uno de los eventos enviados son firmados. Es importante verificar que:
· El evento Webhook se originó desde Pagadito.
· El evento Webhook no fue alterado durante la transmisión.
· El evento Webhook va dirigido al destinatario correcto.
Las siguientes cabeceras se utilizan para proporcionar información para la validación de
la firma.

    · PAGADITO-SIGNATURE: firma asimétrica generada por Pagadito codificada en
         Base 64.

    · PAGADITO-AUTH-ALGO: algoritmo utilizado para generar y verificar la firma
         asimétrica.

    · PAGADITO-CERT-URL: dirección URL para descargar el certificado de llave
         pública X509 para ser utilizado en el proceso de verificación.

La firma se genera mediante la concatenación de cinco datos, utilizando | (barra vertical)
como separador:

    · ID Notificación: Identificador único de la notificación HTTP. Contenida en la
         cabecera PAGADITO-NOTIFICATION-ID.

    · Timestamp Notificación: Timestamp de la notificación HTTP. Contenida en la
         cabecera PAGADITO-NOTIFICATION-TIMESTAMP.

    · ID Evento: Identificador del evento, el cual se incluye en el cuerpo del evento.
    · Cyclic Redundancy Check (CRC32): Checksum CRC32 para el cuerpo de la

         petición HTTP.
    · WSK: Credencial de conexión de la Cuenta Pagadito.

La cadena de entrada para validar la firma tendría la siguiente forma:

                        IdNotificacion|TimestampNotificacion|IdEvento|CRC32|WSK

                                                                                                                    36
El algoritmo de autenticación especificado en PAGADITO-AUTH-ALGO utiliza un
algoritmo de firma asimétrica. Esto permite a Pagadito utilizar una llave privada para
crear la firma en PAGADITO-SIGNATURE, y te permite utilizar una llave pública
contenida en el certificado cuya ruta se define en PAGADITO-CERT-URL para verificar
el evento Webhook.

Leer y verificar webhook
Para poder verificar la notificación webhook debe obtener las cabeceras de la
notificación, el certificado y validar la firma del mensaje.

[ PHP ]

   <?php
      /* Get headers */
      $headers = getallheaders();
      $notification_id = $headers['PAGADITO-NOTIFICATION-ID'];
      $notification_timestamp = $headers['PAGADITO-NOTIFICATION-TIMESTAMP'];
      $auth_algo = $headers['PAGADITO-AUTH-ALGO'];
      $cert_url = $headers['PAGADITO-CERT-URL'];
      $notification_signature = base64_decode($headers['PAGADITO-SIGNATURE']);

      /* Get data */
      $data = file_get_contents('php://input');

      /* Get Event ID */
      $array_data = json_decode($data, TRUE);
      $event_id = $array_data['id'];

      /* Copy from Technical Configuration -> Integration Parameters */
      $wsk = 'SET-YOUR-WSK';

      /* Generate validation string */
      $data_signed = $notification_id . '|' . $notification_timestamp . '|' .
   $event_id . '|' . crc32($data) . '|' . $wsk;

      /* Get content of certificate */
      $http_options = array(

          'http' => array(
              'protocol_version' => '1.1',
              'method' => 'GET',
              'header' => array(
                 'Connection: close'
              ),

          )
      );
      $cert_stream_context = stream_context_create($http_options);
      $cert_content = file_get_contents($cert_url, FALSE,
       $cert_stream_context);

      /* Get public key */
      $pubkeyid = openssl_pkey_get_public($cert_content);

                                                                                                                    38
       /* Verify sign */
       $verification = openssl_verify($data_signed, $notification_signature,
   $pubkeyid, $auth_algo);
       /* Free public key */
       openssl_free_key($pubkeyid);
       /* Validation */
       if ($verification == 1) {

          die(`Valid');
       } elseif ($verification == 0) {

          die(`Invalid');
       } else {

          die(`Error');
        }
   ?>

Respuesta
Cuando una aplicación recibe el evento debe responder con un código de estado HTTP
de nivel 200. Si se responde con cualquier otro código, Pagadito intentará entregar el
evento hasta un máximo de 20 veces en el transcurso de 3 días.
